## 1. เฉลยการบ้าน 1: PizzaFriend Requirements

*📄 แหล่งอ้างอิง: `04_Work_and_Homework/Homework_1_PizzaFriend_Requirements (1).pdf`*

### 1.1 วัตถุประสงค์ของระบบ (System Objective)
ระบบแอปพลิเคชันสั่งพิซซ่าออนไลน์สำหรับร้าน PizzaFriend เพื่อให้ลูกค้าสามารถเลือกหน้า ถาด ขนาด สั่งเดลิเวอรี และชำระเงิน พร้อมระบบแจ้งเตือนสถานะการทำและการจัดส่ง

### 1.2 Functional Requirements (FR)
1. **FR-1 (User Registration & Auth):** ผู้ใช้ต้องสามารถลงทะเบียน เข้าสู่ระบบ และจัดการข้อมูลที่อยู่จัดส่งได้
2. **FR-2 (Custom Pizza Builder):** ระบบต้องอนุญาตให้ลูกค้าปรับแต่งหน้าพิซซ่า ขนาดแป้ง และขอบชีสได้ตามต้องการ
3. **FR-3 (Order Placement & Cart):** ระบบต้องคำนวณราคาสินค้ารวม ค่าจัดส่ง และภาษี พร้อมสรุปก่อนกดยืนยันคำสั่งซื้อ
4. **FR-4 (Payment Gateway):** ระบบต้องรองรับการชำระเงินผ่านบัตรเครดิต, พร้อมเพย์ (PromptPay QR) และเก็บเงินปลายทาง (COD)
5. **FR-5 (Real-time Order Tracking):** ระบบต้องแสดงสถานะคำสั่งซื้อแบบเรียลไทม์ (Received $\rightarrow$ Preparing $\rightarrow$ In Oven $\rightarrow$ Delivering $\rightarrow$ Completed)

### 1.3 Non-Functional Requirements (NFR)
1. **Performance:** ระบบต้องประมวลผลการสั่งซื้อและออกใบเสร็จดิจิทัลให้เสร็จสิ้นภายใน 3 วินาที
2. **Usability:** หน้าจอต้องรองรับ Responsive Design ใช้งานง่ายบนสมาร์ตโฟน มีขั้นตอนการสั่งซื้อไม่เกิน 3 คลิก
3. **Security:** ข้อมูลบัตรเครดิตต้องประมวลผลผ่านระบบมาตรฐาน PCI-DSS และไม่จัดเก็บเลข CVV ในเซิร์ฟเวอร์
4. **Availability:** ระบบต้องมีความพร้อมใช้งาน (Uptime) ไม่น้อยกว่า 99.9% ในช่วงเวลาเปิดร้าน (10:00 - 22:00 น.)

## 2. เฉลยการบ้าน 2: EasyClinic Stakeholders & Roles

*📄 แหล่งอ้างอิง: `04_Work_and_Homework/Homework_2_EasyClinic_Stakeholders.pdf`*

การจำแนกผู้มีส่วนได้ส่วนเสีย 9 กลุ่มของระบบคลินิก EasyClinic:

| ลำดับ | ผู้มีส่วนได้ส่วนเสีย (Stakeholder) | บทบาทในระบบ (Role in System) | ความคาดหวังหลักต่อระบบ |
|:---:|:---|:---|:---|
| **1** | **ผู้ป่วย (Patient)** | ผู้รับบริการ จองคิว ดูประวัติยา และชำระค่ารักษา | จองคิวง่าย ไม่ต้องรอนาน ข้อมูลสุขภาพปลอดภัย |
| **2** | **แพทย์ (Doctor)** | ตรวจรักษา บันทึกเวชระเบียน (EMR) วินิจฉัย และสั่งยา | ดึงประวัติการรักษาและแพ้ยาได้รวดเร็ว แม่นยำ |
| **3** | **พยาบาล (Nurse)** | คัดกรองอาการ วัดสัญญาณชีพ (V/S) จัดคิวตรวจ | บันทึกข้อมูลคัดกรองสะดวก ดูสถานะคิวคนไข้ชัดเจน |
| **4** | **เภสัชกร (Pharmacist)** | ตรวจสอบใบสั่งยา จัดยา ให้คำแนะนำการใช้ยา | ระบบเตือน Drug Interaction (ยาตีกัน) และประวัติแพ้ยา |
| **5** | **เจ้าหน้าที่การเงิน (Cashier)** | คิดค่ารักษา ออกใบเสร็จ และรับชำระเงิน | คำนวณค่ายาและค่าบริการถูกต้อง รองรับทุกช่องทาง |
| **6** | **ผู้จัดการคลินิก (Clinic Manager)** | วางแผนงาน บริหารสต็อกยา และดูรายงานสถิติ | แดชบอร์ดสรุปรายรับ-รายจ่าย และสถิติจำนวนผู้ป่วย |
| **7** | **ผู้ดูแลระบบ (IT Admin)** | จัดการสิทธิ์การเข้าถึง ดูแลฐานข้อมูลและเซิร์ฟเวอร์ | ระบบสำรองข้อมูลอัตโนมัติ จัดการ Role-Based Access ง่าย |
| **8** | **ฝ่ายควบคุมคุณภาพ (QA / Auditor)** | ตรวจสอบมาตรฐานเวชระเบียนและกฎระเบียบสาธารณสุข | บันทึกประวัติการแก้ไขข้อมูล (Audit Log) ครบถ้วน |
| **9** | **ผู้ให้บริการภายนอก (Lab / Partner)** | รับส่งผลตรวจทางห้องปฏิบัติการภายนอกคลินิก | API ส่งผลตรวจเข้าสู่ระบบ EMR อัตโนมัติและปลอดภัย |

## 3. เฉลยการบ้านการสะท้อนจริยธรรม 4 ด้าน ("ฉันจะ...")

*📄 แหล่งอ้างอิง: `04_Work_and_Homework/homework.txt`*

สะท้อนจรรยาบรรณวิศวกรซอฟต์แวร์ในการทำงานจริง 4 ประการ:
1. **ฉันจะไม่ปล่อยโค้ดที่มีช่องโหว่ความปลอดภัยที่ตนเองทราบดีออกสู่โปรดักชัน:** แม้จะมีแรงกดดันเรื่องกำหนดเวลาส่งมอบ เพราะความปลอดภัยของผู้ใช้งานต้องมาก่อนผลประโยชน์ทางธุรกิจระยะสั้น
2. **ฉันจะเคารพและปกป้องข้อมูลส่วนบุคคลของผู้ใช้:** ปฏิบัติตามหลักการรักษาความลับ (Confidentiality) และไม่เปิดเผยหรือนำข้อมูลลูกค้าไปใช้เพื่อประโยชน์ส่วนตน
3. **ฉันจะไม่ละเมิดทรัพย์สินทางปัญญาหรือใช้ซอฟต์แวร์เถื่อนในการพัฒนา:** ใช้เฉพาะโอเพนซอร์สที่มีสิทธิ์ถูกต้องและปฏิบัติตามสัญญาอนุญาต (License) อย่างเคร่งครัด
4. **ฉันจะพัฒนาความรู้และทักษะของตนเองอย่างต่อเนื่อง:** เพื่อส่งมอบชิ้นงานที่มีมาตรฐานสูงสุดตามหลัก ACM/IEEE Code of Ethics

## 4. บันทึกคำถามและคำตอบท้ายคาบ (Handwritten Q&A h1.1 & h1.2)

*📄 แหล่งอ้างอิง: `04_Work_and_Homework/h1.1.jpg` และ `h1.2.jpg`*

* **Q: เพราะเหตุใด ซอฟต์แวร์จึงมีค่าบำรุงรักษา (Maintenance Cost) สูงกว่าค่าพัฒนาเริ่มต้น?**
  * **A:** เนื่องจากระบบจริงต้องใช้งานต่อเนื่องหลายปี และต้องปรับตัวตามความต้องการธุรกิจที่เปลี่ยนไป ฮาร์ดแวร์/OS ใหม่อัปเดต และแก้ไขบั๊กที่พบจากการใช้งานจริง โดยปกติค่า Evolution จะคิดเป็น 60-80% ของ Total Cost of Ownership
* **Q: การทำ Prototyping มีผลต่อ Waterfall Model อย่างไร?**
  * **A:** ช่วยลดความเสี่ยงจากการกำหนดความต้องการผิดพลาด (Requirements Misunderstanding) ในช่วงเริ่มต้น ทำให้ได้สเปกที่แม่นยำก่อนเริ่มเฟส Design & Implementation
